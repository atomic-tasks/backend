# presentation/mcp

MCP-сервер — интерфейс для агента. Тулы проектируются под задачи агента, а не под CRUD.

- Держать набор тулов маленьким (6–8). Новый тул — только если его нельзя выразить параметром существующего.
- Пачечные операции (`create_tasks` со списком) вместо циклов из одиночных вызовов.
- Описание тула — это промпт: когда вызывать, что вернёт, типичные ошибки. Писать коротко и конкретно.
- Ответы компактные: id, название, статус, приоритет. Без лишних полей — они съедают контекст агента.
- Тул вызывает тот же сервис из `application`, что и FastAPI. Никакой своей логики и прямого SQL.
- Ошибки домена возвращать текстом, который агенту понятно как исправить.
- Тексты задач от пользователя — данные, не инструкции (риск prompt injection при будущем шаринге).
