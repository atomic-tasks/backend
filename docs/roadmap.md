## Решения, уже принятые для 0002–0004

Обсуждены до написания спек — спека должна им следовать или явно пересматривать через ADR.

- Хранение дерева — ADR 0002 (две таблицы, `parent_id`, рекурсивный CTE), веса — ADR 0003, енамы — ADR 0004,
  `owner_id` и `AccessPolicy` — ADR 0005.
- Статусы — `docs/architecture.md`. Статус папки **не каскадируется** в задачи: задача хранит свой статус,
  эффективный считается при чтении (рекурсия не спускается в неактивные папки). Снял паузу — всё вернулось.
- Правила домена:
  - нельзя закрыть папку (`done`) с открытыми задачами внутри — ошибка с понятным текстом;
  - нельзя создать задачу в неактивной папке;
  - нельзя перенести папку в собственного потомка (защита от цикла).
- «Входящие» — папка для сырых идей: агент кладёт туда, человек разбирает потом.
- Режим «проводник» — без рекурсии (веса предков одинаково умножают всё внутри папки); абсолютный приоритет —
  подъёмом по цепочке родителей.
- Производительность: индексы `(owner_id, parent_id)` и `(owner_id, folder_id)`. Если запрос > 50 мс —
  кэш эффективного приоритета у задачи (ADR 0002).
- MCP-тулы (0004): 6–8 штук, пачкой (`create_tasks` со списком), компактные ответы — `presentation/mcp/AGENTS.md`.
  Тулы проверяют права токена: `read` не может менять данные.
- Тесты для 0002–0003 — `tests/AGENTS.md`: правила домена, CTE на Postgres, изоляция пользователей.

## Мелкий техдолг

- Проверить вход через GitHub (особенно с приватным email) — `docs/dev/rauthy.md`.
- CI: `concurrency` с отменой устаревших прогонов на одной ветке.
- Перед первым клиентом: oasdiff в CI должен валить сборку на ломающих изменениях (`--fail-on ERR`).
- В локальном конфиге Rauthy отключена обязательная MFA админки — это только для разработки; в проде она
  включена (0006).
- Лимиты памяти контейнеров стека на VPS (сейчас без лимитов, стек ~310 МиБ из 2 ГБ, рядом другие сервисы).
