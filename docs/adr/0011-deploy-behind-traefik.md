# 0011. Деплой: compose за Traefik, выкатка из GitHub Actions через forced command

Статус: принят

## Контекст
Бэкенду и Rauthy нужен публичный HTTPS-адрес (спека 0006). На VPS уже работает Traefik с другими сервисами
и держит 80/443. Релизы публикуются в ghcr по тегу (спека 0005). Репозиторий публичный, в нём не должно быть
ничего о конкретном сервере.

## Решение
- **Один compose-проект** (`deploy/compose.yaml`): Postgres, Rauthy, migrate, API — как локально.
  Rauthy и API подключаются к внешней сети Traefik, маршруты — labels. Своего прокси нет, порты на хост
  не публикуются. Postgres — только во внутренней сети.
- **Хосты.** API — `API_HOST`, Rauthy — `AUTH_HOST`. Отдельный хост IdP позволяет вынести Rauthy на другой
  сервер без смены issuer, а значит без поломки `(issuer, sub)` в `user_identities`.
- **Конфигурация — env.** Всё, что зависит от сервера (хосты, сеть и подсеть Traefik, entrypoint, certresolver),
  — в `.env` на сервере и в переменных GitHub environment `production`. Rauthy берёт `PUB_URL`, `PROXY_MODE`,
  `TRUSTED_PROXIES`, `RP_ID`, `RP_ORIGIN` из env, статичная часть — `deploy/rauthy/config.toml`.
- **Выкатка — джоба `deploy` в `release.yml`**, environment `production` с обязательным подтверждением автора.
  Джоба выполняет `ssh deploy@host X.Y.Z`. На сервере ключ ограничен в `authorized_keys`
  (`restrict,command="deploy.sh"`): можно только выкатить указанную версию. `deploy.sh` скачивает
  `deploy.tar.gz` из GitHub Release этой версии, тянет образ `:X.Y.Z`, применяет миграции и перезапускает API.
  Конфиг стека версионируется вместе с образом.
- **Откат** — та же джоба через `workflow_dispatch` с версией. Миграции назад не откатываются.

## Альтернативы
- **Свой Caddy/nginx в compose** — конфликт за 80/443 с Traefik, второй выпуск сертификатов.
- **`scp` конфига и произвольные команды по SSH из джобы** — проще, но ключ CI даёт shell пользователю
  из группы `docker`, то есть root на общем VPS.
- **Watchtower / автопулл `latest`** — нет контроля миграций и точной версии, откат неявный.
- **Отдельный стек для Rauthy** — отложено до появления других сервисов, которым он нужен.

## Последствия
- Доверие к серверу = доверие к GitHub Releases и ghcr репозитория: бандл и образ оттуда исполняются от
  пользователя из группы `docker`. Публикует их только `release.yml` по тегу на коммит из `main`.
- `deploy.sh` на сервере обновляется руками (он же forced command): новая версия из бандла кладётся рядом
  как `deploy.sh.new`.
- Миграции должны быть совместимы со старым кодом (expand → contract в разных релизах), иначе откат —
  только из бэкапа.
- Перезапуск API даёт несколько секунд недоступности.
