# 0010. Версия приложения из git-тега

Статус: принят

## Контекст

Релиз — тег `vX.Y.Z` (спека 0005). Версия нужна в образе, в `info.version` схемы и в MCP `serverInfo`.
Держать её ещё и в `pyproject.toml` — два источника правды и отдельный PR на каждый бамп.
Сборка — `uv_build`, который динамическую версию (как `hatch-vcs`) не поддерживает, а `.git`
в Docker-контекст не попадает.

## Решение

Источник правды — тег. В `pyproject.toml` постоянная заглушка `version = "0.0.0"`.
Release workflow передаёт версию в Docker как `--build-arg VERSION`, Dockerfile перед установкой проекта
выполняет `uv version --frozen "$VERSION"`. Приложение читает версию из метаданных пакета, как и раньше.

## Последствия

- Бамп версии — это только `git tag`, без коммита.
- Локально и в закоммиченном `openapi.json` версия всегда `0.0.0`; реальная — только в образе и в релизе.
- `uv.lock` хранит корневой пакет как `0.0.0`; на сборку это не влияет (`--frozen`).
- Образ, собранный без `VERSION`, честно показывает `0.0.0`.
