# 0013. Сессии браузера: вход через бэкенд и httpOnly-cookie

Статус: принят. Реализация — спека 0008.

## Контекст

Появляется веб-клиент ([atomic-tasks/web](https://github.com/atomic-tasks/web), его ADR 0003) — SPA
со статикой без своего сервера. Сейчас REST принимает только `Authorization: Bearer` (JWT от Rauthy или PAT).
Если SPA сама проходит вход в Rauthy и держит JWT, токен доступен любому скрипту на странице, а после
перезагрузки его нужно получать заново. Общие гайдлайны требуют на клиентах защищённое хранилище —
в браузере это httpOnly-cookie, которую JS прочитать не может.

## Решение

- **Бэкенд сам проходит вход** (BFF): authorization code + PKCE с Rauthy как конфиденциальный клиент,
  создаёт пользователя по `(issuer, sub)` по тем же правилам, что и для JWT (ADR 0009, спека 0001),
  и заводит **свою сессию**. Токены Rauthy после входа не хранятся и в браузер не попадают.
- **Сессия** — строка в Postgres, в cookie — случайный секрет; в базе только его хеш (как у PAT).
  Cookie `__Host-` с `HttpOnly; Secure; SameSite=Lax; Path=/`.
- **REST принимает cookie-сессию наравне с JWT**: те же права, что у интерактивного входа (в том числе
  управление PAT). Bearer работает как раньше. `/mcp` cookie не принимает.
- **CSRF**: для запросов с cookie-сессией небезопасные методы проверяют `Origin` по списку разрешённых.
- **Один origin для браузера**: сайт на `WEB_HOST`, его `/api/` Traefik отдаёт бэкенду. CORS не нужен.
  Машинные клиенты (MCP, бот, CLI) ходят на `API_HOST` по Bearer; cookie `__Host-` туда не попадает.

## Альтернативы

- **SPA с PKCE и JWT в памяти** — токен доступен скриптам страницы, нужен CORS и тихий повторный вход.
- **Фулстек-фреймворк с сервером у веба** — лишний Node-процесс на сервере, сессия всё равно где-то хранится.

## Последствия

- Бэкенд получает состояние сессий (таблица, срок жизни, очистка) и CSRF-проверку.
- Отзыв доступа мгновенный: удалили сессию — пользователь вышел.
- Веб обязан жить на хосте, где Traefik проксирует `/api` в бэкенд; на чужом домене cookie не сработает.
- Тот же механизм может использовать Flutter-сайт из `mobile-app`, если будет жить на таком же хосте.
