# 0003. Чтение дерева и REST для папок и задач

Статус: реализована

## Зачем

Запись дерева есть (0002), но смотреть его нечем. Эта спека даёт два способа чтения — «проводник» и
«всё вложенное» с приоритетом — и REST поверх сервисов записи и чтения. После неё у клиентов (бот, веб)
есть всё, чтобы показать дерево и ответить на вопрос «за что браться сейчас». MCP-тулы (0004) будут
вызывать тот же `TreeService`.

## Сценарии

Все сценарии — от имени `Identity`. Чтение требует scope `read`, изменения — `write` (как в 0002).

1. **Проводник.** Пользователь открывает папку и видит:
   - саму папку и путь к ней от корня (хлебные крошки);
   - прямые подпапки и задачи этой папки, у каждой — абсолютный приоритет (от корня);
   - признак, активна ли ветка: папка и все её предки в `active`.
   По умолчанию закрытые (`done`, `cancelled`) подпапки и задачи скрыты; `include_closed` показывает их.
2. **Всё вложенное.** Пользователь выбирает папку (обычно корень) и получает плоский список задач
   из всего её активного поддерева, отсортированный по приоритету — сверху то, что делать сейчас.
   У каждой задачи — приоритет относительно выбранной папки и путь от выбранной папки до папки задачи.
3. **REST над записью.** Создать, изменить, перенести, сменить статус, удалить папку или задачу —
   тонкие эндпоинты над `FolderService` и `TaskService` из 0002.

## Правила и ограничения

**Приоритет** (ADR 0003)
- Приоритет в «всём вложенном» — произведение весов папок от выбранной папки (не включая её) до задачи
  и веса самой задачи. Задача весом 1.0 прямо в выбранной папке имеет приоритет 1.0.
- Абсолютный приоритет в «проводнике» — произведение весов всех предков от корня, самой папки и
  элемента. Множитель предков считается один раз подъёмом по цепочке родителей, без рекурсии вниз.
- Приоритет считается из `Decimal` без потери точности; наружу — число.

**Всё вложенное**
- Рекурсия спускается только в подпапки со статусом `active`. Неактивная подпапка прячет всю ветку,
  статусы внутри не меняются (0002).
- Выбранную папку обходим всегда, даже если она сама или её предок неактивны: пользователь выбрал её явно.
- По умолчанию в список попадают задачи `todo` и `in_progress`; параметр `status` задаёт другой набор.
- Порядок: приоритет по убыванию; при равенстве — `in_progress` раньше `todo` (начатое — доделать),
  затем старшие по дате создания, затем `id` — детерминированно, чтобы `limit` не «прыгал».
- `limit`: по умолчанию 50, не больше 500. Курсоров нет — личные объёмы.
- Цикл в данных (появившийся в обход проверок, см. риски 0002) не зацикливает запрос.

**Проводник**
- Без рекурсии вниз: два запроса по индексам `(owner_id, parent_id)` и `(owner_id, folder_id)`.
- Порядок: открытые раньше закрытых, затем вес по убыванию, затем дата создания.
- Все дети одной папки, без `limit`.

**Доступ**
- Доступ к выбранной папке — через `AccessPolicy`; чужая или несуществующая — 404.
- Рекурсия и запросы детей ограничены `owner_id` выбранной папки.

**REST**
- Всё под `/api/v1`, требует аутентификации. `operation_id` — имя функции роутера, стабильное.
- Роутеры не проверяют правила домена и не дублируют валидацию: поля проверяет домен, ошибки —
  problem details (RFC 9457).
- Ошибки состояния дерева (непустая папка, открытое внутри, неактивная папка, `done`-предок, цикл,
  защита корня) — 409; неверное поле — 422; нет прав токена — 403; не найдено — 404.
- В `PATCH` отсутствующее поле не меняется; `description: null` или `""` очищает описание.

## Вне рамок

- MCP-тулы — спека 0004.
- Вложенное дерево (папки с задачами внутри) одним ответом — клиент собирает его из проводника.
- Курсорная пагинация, полнотекстовый поиск, фильтры по датам.
- Кэш эффективного приоритета у задачи (ADR 0002) — только если запрос станет медленнее 50 мс.
- Ручной порядок внутри папки, теги, дедлайны.
- Экспорт `openapi.json` и стабилизация схемы для SDK — спека 0005.
