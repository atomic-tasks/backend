# 0005. Экспорт openapi.json и релизный workflow

Статус: реализована

## Зачем

Клиенты (бот, web, Flutter) генерируют SDK из `openapi.json` бэкенда и закрепляют конкретную версию
(`guides/api-contract.md`). Деплою (0006) нужен готовый образ с понятным тегом. Сейчас нет ни того, ни другого:
схема доступна только у запущенного сервера, образ собирается в CI без публикации.

## Сценарии

- **Разработчик меняет API.** Перегенерирует `openapi.json` одной командой и коммитит вместе с кодом.
  В PR изменение контракта видно диффом. Если забыл — CI падает с подсказкой, какую команду запустить.
- **PR ломает контракт** (удалён эндпоинт, поле стало обязательным и т. п.). CI показывает список ломающих
  изменений относительно базовой ветки — аннотациями в PR и в summary прогона. Сборку не валит.
- **Автор выпускает релиз.** Пушит тег `vX.Y.Z` на коммит из `main`. Workflow собирает образ с версией из тега,
  публикует его в `ghcr.io/atomic-tasks/backend` и создаёт GitHub Release с `openapi.json` этой версии
  и сгенерированными release notes.
- **Клиент обновляет SDK.** Скачивает `openapi.json` из нужного релиза (или берёт файл из репозитория на теге).

## Правила и ограничения

- `openapi.json` лежит в корне репозитория, генерируется командой `python -m atomic_tasks openapi`,
  руками не правится.
- Схема не зависит от окружения: экспорт игнорирует `.env` и переменные окружения, берёт настройки по умолчанию.
  Поэтому в схеме адреса IdP — локальные по умолчанию; генераторам SDK они не важны.
- Версия приложения берётся из git-тега (ADR 0010). В `pyproject.toml` — заглушка `0.0.0`, её же видят
  локальный запуск и закоммиченный `openapi.json`. Версию в образ передаёт `--build-arg VERSION`.
- Релиз — только тег вида `vX.Y.Z` (SemVer без суффиксов) на коммит, входящий в `main`. Иначе workflow падает
  до публикации.
- `openapi.json` в релизе экспортируется из опубликованного образа — это ровно та схема, которую отдаёт сервер
  этой версии. Перед публикацией релиза она сверяется с закоммиченной (без `info.version`).
- Теги образа: `X.Y.Z`, `X.Y`, `latest`. Платформа — только `linux/amd64`.
- Workflow запрашивает только нужные права: `contents: write` (релиз) и `packages: write` (ghcr).

## Вне рамок

- Валить CI на ломающих изменениях — включим перед первым клиентом.
- arm64-образ, подпись образа и attestations (cosign, SLSA).
- Автоматический выбор версии (release-please, semantic-release), CHANGELOG.md.
- Деплой образа — спека 0006.
- Публикация SDK-пакетов из бэкенда: SDK генерируют клиенты у себя.

## Открытые вопросы

- Пакет в ghcr после первой публикации может оказаться приватным — сделать публичным в настройках пакета
  (разово, руками).
