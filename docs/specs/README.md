# Specs

Spec-driven development: фича начинается со спеки, реализация идёт по её `tasks.md`.

```
NNNN-feature-name/
├── spec.md   # что и зачем: сценарии, правила, вне рамок
├── plan.md   # как: слои, файлы, порты, миграции, тулы, эндпоинты
└── tasks.md  # шаги реализации с критериями готовности
```

Новая спека — скилл `/new-spec` или копия `_template/`.
Спеки коммитятся и остаются после реализации: это история того, почему система устроена так.
Расхождение кода со спекой исправляется правкой спеки, а не молчанием.
