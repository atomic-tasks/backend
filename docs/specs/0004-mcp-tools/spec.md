# 0004. MCP-тулы и финальный скилл декомпозиции

Статус: реализована

## Зачем

Дерево можно писать и читать через REST (0002–0003), но главный клиент по `docs/intent.md` — агент.
Эта спека даёт ему набор MCP-тулов на `/mcp` поверх тех же сервисов и финальную версию скилла
декомпозиции (`skills/task-decomposition/SKILL.md`). После неё автор подключает AtomicTasks к Claude Code
по personal access token и раскладывает цели прямо из разговора.

## Сценарии

Все тулы — от имени `Identity` из `McpAuthMiddleware` (PAT или JWT). Чтение требует scope `read`,
изменения — `write`; проверку делают сервисы, как в REST.

1. **Сориентироваться.** Агент открывает корень (или папку по id) и видит путь, подпапки и задачи
   с приоритетом — чтобы найти подходящее место и не создать дубль.
2. **Что делать сейчас.** «За что взяться?» — плоский список открытых задач поддерева по приоритету.
3. **Разложить цель.** Пользователь подтвердил предложенную структуру — агент одним вызовом создаёт
   ветку: папки с подпапками и задачами любой вложенности под указанной папкой.
4. **Отметить прогресс.** «Сделал первые три, четвёртую отменяю» — один вызов со списком смены статусов.
5. **Поправить.** Переименовать, сменить вес или описание, перенести папку или задачу; удалить.
6. **Сырая идея.** Пользователь делится мыслью — агент кладёт её задачей в папку «Входящие» под корнем
   (по правилам скилла; если папки нет — создаёт её).

## Тулы

Семь штук. Имена — глагол + объект, `snake_case`.

| Тул | Что делает | Сервис |
|---|---|---|
| `browse_folder` | Проводник: путь, подпапки, задачи с абсолютным приоритетом. Без `folder_id` — корень | `TreeService.browse`, `FolderService.get_root` |
| `list_next_tasks` | «Всё вложенное»: задачи поддерева по приоритету. Без `folder_id` — от корня | `TreeService.nested_tasks` |
| `create_tree` | Создаёт под `parent_id` вложенную структуру папок и задач, атомарно | новый метод, см. plan |
| `set_status` | Меняет статусы списка папок и задач по порядку, атомарно | новый метод, см. plan |
| `update_item` | Меняет название, описание, вес и/или переносит (`parent_id`) одну папку или задачу | `FolderService`, `TaskService` |
| `delete_item` | Удаляет одну папку (непустую — с `recursive`) или задачу | `FolderService`, `TaskService` |
| `get_item` | Одна папка или задача целиком, с описанием | `FolderService.get`, `TaskService.get` |

## Правила и ограничения

**Тулы**
- Тулы — тонкие адаптеры: разобрать аргументы, вызвать сервис, сжать ответ. Своих проверок нет.
- Тип узла агент передаёт явно: `kind: "folder" | "task"`. Он видит его в ответах чтения.
- Описание тула — промпт: когда вызывать, что вернёт, типичные ошибки. Тексты пользователя в описания
  и `instructions` сервера не попадают.
- Аннотации MCP: чтение — `readOnlyHint`, `delete_item` — `destructiveHint`.

**Ответы — компактные**
- Узел в списке: `id`, `title`, `status`, `priority` (округлённый до 3 знаков); тип понятен из списка
  (`folders`/`tasks`). У задачи во «всём вложенном» — путь из названий папок строкой (`"Go / Конкурентность"`).
- Описания в списках не отдаются — только в `get_item`. Вес — только в `get_item` и в ответе изменения.
- Ответ записи — созданные или изменённые узлы в том же компактном виде, чтобы агенту не нужно было
  перечитывать дерево ради id.
- Формат — структурированный вывод MCP (JSON со схемой); в текстовой части тот же JSON без отступов.

**`create_tree`**
- Вход: `parent_id` и списки `folders`/`tasks`; у папки — `title`, `description?`, `weight?` и свои
  вложенные `folders`/`tasks`. Без веса — 1.0.
- Всё или ничего: одна транзакция; ошибка в любом узле — не создаётся ничего.
- Ошибка указывает на узел: путь из индексов (`folders[1].tasks[0]`) и текст доменной ошибки.
- Лимиты: не больше 100 узлов и 5 уровней вложенности за вызов — защита от случайной «простыни»;
  превышение — понятная ошибка до обращения к базе.

**`set_status`**
- Вход: список `{kind, id, status}`, до 100 элементов. Применяется по порядку, атомарно.
- Порядок важен и работает: «закрыть задачи, затем их папку» в одном вызове проходит — каждое правило
  видит изменения предыдущих элементов.
- Ошибка — индекс элемента и текст доменной ошибки; ничего не меняется.

**Ошибки**
- Доменные ошибки, «не найдено», нехватка scope — результат тула с `isError` и текстом, который объясняет,
  что исправить. Без стектрейсов и внутренних деталей.
- Чужой или несуществующий id — «не найден», как в REST.

**Скилл**
- Финальная версия `skills/task-decomposition/SKILL.md`: использует реальные имена тулов, порядок
  «посмотреть → уточнить → предложить → дождаться подтверждения → создать одной пачкой», правила
  атомарности задач и весов, «Входящие» для сырых идей, отмена (`cancelled`) вместо удаления, если
  пользователь не просил удалить.
- Инструкция по подключению: `claude mcp add` с PAT и установка скилла — в README.

## Вне рамок

- OAuth для коннектора в приложении Claude — спека 0007. Сейчас только PAT и JWT в заголовке.
- Системная папка «Входящие» на бэкенде (автосоздание, защита от удаления) — пока это соглашение скилла.
- Пачечные `update`/`move`/`delete` — по одному элементу, пока опыт не покажет, что пачка нужна.
- MCP resources и prompts — только tools.
- Скрытие тулов записи для `read`-токена в `tools/list` — сервис и так вернёт понятную ошибку.
- Поиск по названию, фильтры по датам, пагинация.
- Публикация скилла в маркетплейс плагинов.
